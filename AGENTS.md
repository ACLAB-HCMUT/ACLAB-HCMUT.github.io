# AGENTS.md — ACLAB HCMUT Website

Guidance for AI agents. Read first; follow across sessions. Keep this file concise and current.
Human contributors: see [`CONTRIBUTING.md`](./CONTRIBUTING.md).

## What
Public website for **ACLAB (Advanced Computing Lab), HCMUT**. **Docusaurus 3.6** (TS + React),
deployed to `https://aclab-hcmut.github.io` (GitHub Pages, org `ACLAB-HCMUT`).
**Bilingual: English source + Vietnamese mirror — ship both.**

## Commands
- `npm run start` — dev server · `npm run start -- --locale vi` — preview VI ·
  `npm run build` — prod build (`onBrokenLinks: 'throw'` → a broken internal link **fails the
  build**) · `npm run typecheck` (`tsc`) · `npm run serve`.
- Before finishing a change: run `typecheck`, and `build` if you touched links/docs/config/components.
- **Restart the dev server after editing `docusaurus.config.ts` / `sidebars*.ts` /
  `_category_.json`** — these don't hot-reload and can leave routes crashed in dev while `build`
  still passes. Fix: `npm run clear && npm run start`.
- **Deploy:** `.github/workflows/deploy.yml` auto-builds + deploys on push to `main` (`npm ci` →
  build). Requires Settings → Pages → Source = "GitHub Actions". `build/` is generated — **never
  edit or commit it** (legacy-tracked; keep it out of new commits).
- **Private docs:** `docs:decrypt` / `docs:encrypt` / `docs:verify` / `docs:check` / `docs:clean`
  / `docs:diff-private` — see **Encrypted internal docs** below.

## Architecture & system requirements
- **Static site, no backend.** Everything is prerendered at build time and served from GitHub
  Pages. No server code, DB, or runtime secrets. Any dynamic behavior is **client-side only**.
- **SSR-safe is mandatory.** Pages are server-rendered during `build`. Code that touches
  `window`/`document`/`canvas`/WebGL **must not run during SSR** — wrap it in `@docusaurus/
  BrowserOnly` + `React.lazy` (see `ClientLazy`, Design patterns). A direct top-level import of a
  browser-only lib in an SSR path breaks the build.
- **`onBrokenLinks: 'throw'`** — every internal link must resolve or the build fails. Cross-link
  with site-absolute paths (`/docs/...`).
- **Build covers all locales** (`en`, `vi`). Both must compile. **Commit `i18n/`.**
- **Node ≥ 18.** Dependencies resolve cleanly with plain `npm ci` — keep it that way: do **not**
  reintroduce `@react-three/fiber`, whose optional RN/expo peer forces `@types/react@19` and
  breaks install.
- **Performance budget:** lazy-load heavy libs per-page (never in the shared bundle); gate large
  assets (e.g. 3D models) behind a click-to-load poster; respect `prefers-reduced-motion`.

## Structure
- **React pages** `src/pages/*.tsx`: index, about, research, projects, people, partners, contact,
  join, board-demo (CSS viewer demo). `ui-showcase` = three.js hero + 3D model demo.
- **Shared UI kit** `src/components/` — split into focused modules, re-exported by the
  `index.tsx` **barrel** (import everything from `'../components'`):
  `types.ts` (`Project`/`Member`/`NewsItem`/`ProjectStatus`), `primitives.tsx`
  (Container/Btn/Grid/Arrow), `sections.tsx` (Section/SectionHead/PageHero/Breadcrumb/CTABanner),
  `tags.tsx`, `cards.tsx` (ResearchCard/ProjectCard/MemberCard/NewsCard/Partner),
  `blocks.tsx` (**reusable layout/content blocks**: Split, FeatureCard, IconTile, Timeline,
  InfoCard, ProfileHeader), `stats.tsx` (CountUp/StatItem). Styles in `ui.module.css`.
  **Prefer composing these blocks over page-specific one-off CSS modules.** Card CTAs and kit
  text use `<Translate>` (extract with `write-translations`, fill `i18n/vi/code.json`).
- **Viewers** `src/components/viewers/` — reusable, client-only 3D + PCB viewers (see Design
  patterns). `chrome.tsx` holds the shared `ViewerFrame`/`LoadingOverlay`/`ErrorOverlay`/
  `ClientLazy`. Registered as MDX globals in `src/theme/MDXComponents.tsx`.
- **3D / WebGL** `src/components/hero3d/` — `<Hero3D>`, an interactive **three.js** particle
  scene used as the **homepage hero** backdrop and on **`/ui-showcase`** (the 3D/UI demo + 3D lab
  equipment gallery). Plain `three`, no R3F.
- **Data — edit these, not JSX** (`src/data/`): `projects.ts` (`featuredProjects = slice(0,3)`),
  `people.ts` (`peopleGroups`, `peopleHighlight`), `site.ts` (`partners`, `stats`),
  `research.ts` (a project's `area` must equal a research `title`).
- **Docs instances** (sidebars **autogenerated** from folders + `_category_.json` — edit
  `position`/`label` there, not `sidebars*.ts`):
  - `docs/` → **Knowledge Base**, `routeBasePath: docs`, sidebar `knowledgeBase` (`sidebars.ts`).
  - `courses/` → **Courses**, id `courses` (`sidebarsCourses.ts`).
  - `guide/` → **BKU Student Guide**, id `guide` (`sidebarsGuide.ts`).
  - Blog `blog/` → **News & Events** (`/blog`).
- **Config** `docusaurus.config.ts`. **Ambient types** `src/types/*.d.ts`. **Static assets**
  `static/` (member photos `static/img/people/`; models/boards/posters `static/assets/`).

## Encrypted internal docs (private)
Client-side–encrypted internal docs for a static site (no backend/DB/auth server). Only ciphertext
is ever committed or deployed; decryption happens in the browser (or locally via scripts) after a
password is entered. **Never write the password into any file (incl. this one), env, CLI arg, or
git.** Prompted interactively only.
- **Plaintext source** `docs/protected/**/*.md` — **gitignored** AND **excluded from the docs
  build** (`docs` preset `exclude: ['protected/**']`) so it's never rendered, indexed, or in
  sitemap/RSS. Exists only transiently between `docs:decrypt` and `docs:encrypt`.
- **Committed ciphertext** `static/protected/` → served at `/protected/*`: `manifest.json`
  (encrypted list of docs+images) + `docs/**/*.{md,png,jpg,…}.enc` (one AES-256-GCM envelope per
  file, unique salt+IV+tag, versioned). Images are encrypted as **binary**; manifest entries carry
  `type: 'doc'|'asset'` (+ `mime` for assets). In the browser, a doc's relative `<img src>` is
  resolved against the doc path, the matching asset is decrypted to an **in-memory blob URL**
  (revoked on lock) — no plaintext image is ever served.
- **Crypto** (`scripts/lib/crypto.mjs` ↔ browser `src/lib/protectedCrypto.ts` — keep in sync):
  `PBKDF2-SHA256(210k, "username:password", master salt)` → **deriveBits** → HKDF key; per file
  `HKDF-SHA256(per-file salt, info=path)` → **AES-256-GCM**. Wrong password/tamper → auth failure →
  **single generic error** (never "wrong password" vs "corrupt"). ⚠️ Browser MUST use PBKDF2
  `deriveBits`→`importKey('HKDF')`; deriving an HKDF key via PBKDF2 `deriveKey` throws.
- **Viewer** `src/pages/internal.tsx` (`/internal`, navbar "Internal Docs 🔒"): SSR-safe
  `BrowserOnly`; unlock screen → in-memory-only on-demand decryption (reload = locked; nothing in
  localStorage/IndexedDB); lock menu. Uses `marked` (now a **declared dependency**) to render.
- **Scripts** (plain Node `.mjs`, no `tsx`): `docs:decrypt` (restore plaintext), `docs:encrypt`
  (encrypt→verify→atomic replace→remove plaintext→cleanup orphans), `docs:verify` (round-trip +
  missing/orphan), `docs:check` (block staged/leaked plaintext), `docs:clean`, `docs:diff-private`
  (→ gitignored `.private-review/`, never upload).
- **Protection** pre-commit hook via `.githooks/` (installed by `prepare` = `install-hooks.mjs`,
  no husky) runs `docs:check`; gitignore covers `docs/protected/`, `.private-*`, `*.key`, `.env`,
  `credentials.json`. Limitations documented in `README.md` (not per-user auth; password strength
  is everything; no revocation).

## Design patterns (follow these; don't reinvent)
- **Barrel UI kit.** Components live in small files; `src/components/index.tsx` only re-exports.
  Add a component to the right module, then it's available from `'../components'`.
- **Data-driven pages.** Pages map over `src/data/*`; never hardcode lists of people/projects/etc.
  in JSX. Derived figures (e.g. `stats`) should trace to real records.
- **Client-only lazy boundary.** Heavy/browser-only widgets = a thin SSR-safe wrapper
  (`useBaseUrl` + `ClientLazy`) + a `*Impl.tsx` that holds the real imports and runs only in the
  browser. Copy `Model3D`/`GerberViewer` when adding a new viewer.
- **Shared viewer chrome.** Reuse `ViewerFrame` (framed vs `bare`), `LoadingOverlay`,
  `ErrorOverlay` — don't re-style frames/spinners per viewer.
- **Poster gate for heavy assets.** Large models pass `poster=` so the 3D engine loads only on
  click (`Model3D`/`DeviceModel`).
- **three.js for rich 3D UI — lean into it.** Prefer plain **`three`** for custom 3D/animated
  visuals (hero backdrops, scenes, lab/equipment showcases); copy `<Hero3D>`/`ParticleField` as
  the template. Always: `BrowserOnly` + `React.lazy` (SSR-safe), **dispose** geometries/materials/
  renderer + remove listeners on unmount, cap DPR (≤2), and render a single static frame under
  `prefers-reduced-motion`. Use `online-3d-viewer`/`<DeviceModel>` only to *load model files*
  (STEP/GLB). **Do not** add `@react-three/fiber` (peer-dep conflict — see Architecture).
- **MDX globals for reuse in content.** Register doc-embeddable components in
  `src/theme/MDXComponents.tsx` so any `.md`/`.mdx` uses them with no import:
  `<DeviceModel>`, `<Model3D>`, `<GerberViewer>`.
- **Controlled vs uncontrolled.** Components like `GerberViewer` accept an optional `side` (+
  `showControls`) to be page-driven, else self-manage — mirror this for new interactive parts.

## Adding new knowledge — routing guide
When given content to add, **infer the destination from this table**, state it in one line, then
write it. Always create the EN source **and** its VI mirror in the same change.

| What the user is giving you | Goes to | Notes |
|---|---|---|
| Technical how-to / reference (firmware, PCB, ROS, AI/edge, DevOps, equipment) | `docs/<pillar>/` | Pick the matching pillar; new pillar folder only if none fits |
| A hands-on course lab / lecture | `courses/microcontroller/` or `courses/iot/` | New course = new folder + `_category_.json` |
| Student/career/curriculum advice for HCMUT CSE students | `guide/` | Flat; set `sidebar_position` |
| A finished project write-up | `docs/projects/<slug>.md` | Then wire a card in `src/data/projects.ts` (`to: /docs/projects/<slug>`) |
| News / event / announcement | `blog/YYYY-MM-DD-<slug>.md` | News & Events |
| A person, partner, stat, or research area | `src/data/*.ts` | Edit data, not JSX |
| An interactive 3D model / PCB | `static/assets/...` + embed `<DeviceModel>`/`<GerberViewer>` | Add a `poster` for big models |

**Decision rule:** *evergreen reference* → `docs/`; *teachable lab* → `courses/`; *navigating the
degree* → `guide/`; *dated/one-off* → `blog/`; *structured site entity* → `src/data/`. Extending an
existing topic → add a file **inside that pillar folder**, don't make a new category. Genuinely
ambiguous → ask once with a recommendation.

**New docs/courses page:** (1) create the English `.md` (front matter `title`, `sidebar_position`;
new folder → `_category_.json` + `index.md`); (2) create the VI mirror at the parallel i18n path,
translating only prose + `title:`; (3) cross-link with `[text](/docs/...)`, `npm run build` to
check links, restart dev server if you touched a folder/`_category_.json`.

## Conventions
- **Bilingual (EN + VI) — ship both.** Author EN in `docs/`/`courses/`/`guide/`; put VI in the
  **mirrored i18n path** (never inline VI in the English source):
  - `docs/<p>` → `i18n/vi/docusaurus-plugin-content-docs/current/<p>`
  - `courses/<p>` → `i18n/vi/docusaurus-plugin-content-docs-courses/current/<p>`
  - `guide/<p>` → `i18n/vi/docusaurus-plugin-content-docs-guide/current/<p>`
  - `blog/<p>` → `i18n/vi/docusaurus-plugin-content-blog/<p>`
  Translate prose + `title:`; keep `slug`/`sidebar_position`/links/code blocks unchanged. UI labels
  live in `i18n/vi/*.json`; React pages localize via `<Translate>` + `i18n/vi/code.json` (when you
  change a `<Translate>` string, update its `code.json` key or it falls back to English). Keep
  proper names with diacritics ("Lê Trọng Nhân", "Bách Khoa").
- **Only real, verifiable data.** No inflated stats or placeholder people — if it isn't real, hide
  it. Replace placeholders only with user-provided data.
- **Concise & scannable.** Short content; bullets over paragraphs; tables/admonitions for
  structure. Don't pad.
- **Don't hardcode content in JSX** — edit `src/data/*`; pages map over it.
- **Course page** shape: Overview → Objectives → Hardware/Tools → Exercises → Report/Submission →
  Resources.
- **Project card** optional `to` → its wiki (`/docs/projects/<slug>`); else `/projects#<slug>`.
- **Member card** optional `photo` (`/img/people/<file>`) else initials. Agents can't write images
  — wire the path and ask the user to drop the file in `static/img/people/`.
- **Verify names before relying on them** — paths/symbols here may drift.
